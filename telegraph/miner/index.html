How the Miner works

Contract→Validation→RPC / verification→Proxy resolution→Capabilities→Evidence→Machine result

Capabilities

  • Ownership / control
  • Upgradeability
  • Pause
  • Mint authority where evidence permits

Failure semantics

  • Conclusive
  • Inconclusive
  • Unavailable
  • Provider / infrastructure failure

Evidence hierarchy

Verified ABI/source is preferred. Structural evidence is used where legitimately supported. Bytecode fallback is instruction-boundary aware and never treated as authoritative semantic proof.

Application failures are not silently converted into safe or negative findings.
